# Setu Business And Product Overview

## 1. Product summary

Setu is a local-first evidence studio for petition preparation. It is designed to help a reviewer transform a raw folder of mixed evidence into a structured, traceable review workspace without losing the original files or the reasoning path that led to each organizational decision.

The current product emphasis is not autonomous petition drafting. It is evidence intelligence, evidence organization, and evidence review.

## 2. Core business problem

Evidence preparation is often slowed down by three recurring failures:

1. evidence is trapped in unstructured folders
2. interpretation work is manual and repetitive
3. later legal organization loses traceability back to the exact source files

Setu addresses this by building a layered review system where each pass adds structure without hiding the earlier one.

## 3. Core objective

Setu’s objective is to help practitioners and reviewers reach a review-ready evidence set faster while increasing confidence in:

- what each file is
- why it matters
- how it connects to a larger event or initiative
- where it belongs in downstream legal organization
- what still needs human review

## 4. Primary users

### Primary reviewer

The current product is designed first for a reviewer who needs to:

- upload one candidate’s evidence folder
- inspect AI summaries
- see evidence grouped into events
- see events grouped into criteria
- override anything that feels wrong

### Petition preparation operator

The product also supports a more operational user who needs:

- repeatable workspace isolation
- persistent storage
- export packaging
- cost visibility
- local control of prompts and settings

### Future contributors

Because the system is evolving quickly, another important user is the next engineer or AI collaborator who needs enough clarity to continue work safely.

## 5. Product principles

The product is built around the following principles:

1. local-first by default
2. AI-first interpretation, human-final judgment
3. reversible organization layers
4. candidate-centered evidence context
5. no silent loss of source traceability
6. dense, usable review UX over decorative empty space

## 6. What Setu is today

Setu is currently a multi-pass evidence workbench with:

- workspace-based intake
- document summarization
- event bundling
- bundle-level EB1A classification
- document-level tagging
- human overrides
- evidence preview
- output packaging

The current product is not merely a search tool and not merely a document manager. It is a review system built around progressive interpretation.

## 7. Value proposition

### Faster intake

Raw folders become organized workspaces without manual file-by-file triage.

### Better traceability

The system preserves:

- original file access
- per-document summaries
- event-level grouping
- criterion-level organization

### Safer human review

Reviewers can override categories, event assignments, and evidence states instead of being locked into AI decisions.

### Local control

The app runs locally, stores its state locally, and keeps the evidence library isolated per workspace.

## 8. Product workflow

The live operating flow is:

1. set candidate identity
2. upload a folder
3. run indexing
4. let Setu summarize documents
5. let Setu bundle evidence into events
6. let Setu classify events into EB1A criteria
7. let Setu tag individual evidence files
8. review, override, and package the results

This is intentionally progressive. Later passes do not erase earlier ones.

## 9. Product surfaces

### Dashboard

The dashboard is meant for intake, oversight, recent workspace access, and ready-state review.

### Dedicated review page

The review page is meant for more focused retrieval, dense review, and manual override workflows.

### Prompt Library

Prompt Library is intended for controlled prompt adjustment rather than freeform prompt history management.

## 10. Experience goals

The intended experience is:

- calm rather than noisy
- dense but readable
- local and trustworthy
- visually branded without becoming ornamental
- powerful for reviewers who need to move quickly

Recent UX guardrails already established in the product:

- ready-state review returns to the landing page
- large dead areas are treated as UX regressions
- panels should use available real estate well
- prompt editing must be scrollable
- context menus must not open off-screen
- evidence, bundle, and criterion relationships must be easy to read

## 11. Non-goals for the current branch

The current branch is not trying to become:

- a fully autonomous legal drafting engine
- a generic enterprise document management platform
- a multi-tenant cloud collaboration product
- a final conversational knowledge assistant with universal grounded chat

Those may become future phases, but they are not the current product contract.

## 12. Success indicators

The most useful product signals for this stage are:

- fewer manual hours spent organizing raw evidence
- faster transition from folder upload to review-ready workspace
- higher confidence in event grouping and criterion placement
- lower confusion during review
- successful export packaging for downstream drafting

## 13. Operational posture

Setu is intentionally conservative in three places:

- it keeps originals intact
- it isolates folder workspaces
- it exposes override paths instead of hiding AI uncertainty

That posture is more important than making the system feel magically automatic.

## 14. Brand posture

The user-facing product brand is now `setu`, presented through a charcoal-and-amber visual system. Older names may still exist in some internal file names or branch history, but the current product story and user-facing documentation should refer to Setu.
